Jade HUD for Core Keeper

Client-side hover box built on the official Mod SDK. Shows item or object name, what breaks it, and where it comes from.

Checklist

  • Game installed (Mono build, Steam).
  • Official Mod SDK cloned to sdk/.
  • Game code decompiled to _decomp/ for reading (do not commit or share).
  • Install Unity Hub and editor 6000.0.59f2 with "Linux Build Support (Mono)". Needs a Unity login.
  • Open sdk/ in Unity, create the mod in the PugMod window, then add the script.
  • Spike: log the name of the entity under the mouse.
  • Build the hover box from the game's own tooltip prefab.
  • Final check in a peaceful creative world (1920x1080, GUI scale 2). Screenshots before and after.

What the code shows

Read in the game code:

  • API.Client gives LocalPlayer, World, GetGraphicalGameObject(Entity), GetEntity(GameObject), and OnObjectSpawnedOnClient. This is the bridge from the world to ECS data.
  • ObjectDataCD.objectID on an entity, then PugDatabase.GetObjectInfo(id), gives icon, smallIcon, rarity, objectType, tags.
  • PlayerController.GetObjectName(...) returns the localized name the game itself shows.
  • The game already has a tooltip prefab: SlotHoverTooltip (title, icon, background, tags container, coin row). UIMouse owns it as slotHoverTooltip. Reusing it gives the exact game look.
  • API.ModLoader.LoadedMods lists mods with Metadata. API.Localization and API.Config exist.
  • Harmony patches are supported. Burst code can't be patched.

Not yet known:

  • How the game finds the world object under the cursor. I found no helper. Fallback: convert the mouse to a world point (Camera.ScreenToWorldPoint) and query entities near it.
  • Which mod owns an ObjectID. The ID class is empty for mods, so ownership may need a lookup from each mod's loaded assets.
  • "Tool that breaks it". There is no per-object tool field. The only hints are components: DiggableCD (shovel-type digging), MineableCD and TileDamageTagCD (pickaxe-type), HealthCD and DamageableObjectCD (anything with a weapon). The mapping from these to a tool name is my guess and needs in-game testing.

Hover box design

┌──────────────────────────┐
│ [icon]  Copper Ore       │  name, rarity colour
│ ──────────────────────── │
│ [tool]  Pickaxe          │  tool icon + name
│ [src ]  Core Keeper      │  game or mod name, dim
└──────────────────────────┘
  • Reuse SlotHoverTooltip visuals: its background sprites, PugText font, tag styling. No new fonts or colours.
  • Top center, below the health bar, so the cursor stays clear.
  • Shown only when an object is under the cursor and no inventory tooltip is open.
  • Icons from ObjectInfo.smallIcon at whole-number scale.
  • Needs no server install: a client system only reads data. To be confirmed on a dedicated server.

Plants: growth stage and time to next stage

Added at your request. Shows "Growing, stage 2 of 4, next stage in 1m 20s" or "Ready to harvest".

  • GrowingCD.currentStage is synced to clients. The last stage comes from ObjectPropertiesCD (HasReachedFinalStage). Ready to harvest = final stage reached.
  • GrowTimerCD (Value, StageTime) sits on a separate timer entity (GrowTimerRefCD) and has no ghost fields. On a remote multiplayer client it is probably not visible, so the time-to-next-stage row would work in single player and when hosting only. To be tested.
  • Time left per stage is my reading of Value against StageTime. Unverified until tested in game.
